const spinner = document.createElement("span");
spinner.className = "spin";           // .spin { color: green }
section.appendChild(spinner);
setInterval(() => {
  spinner.textContent = frames[n++ % frames.length];
}, 30);                               // no render call — mutations paint

A NERDTree-style file browser in ~200 lines of vanilla DOM: querySelectorAll for the rows, classList for the selection, keydown for the keys, scrollIntoView() for the camera.

document.addEventListener("keydown", (ev) => {
  if (ev.key === "j") select(selected + 1);
  if (ev.key === "Enter") expand(rows()[selected]);
});

Why it can do this

  • A real DOM — JSDOM underneath; anything that renders to the DOM renders to the terminal.
  • Real CSS layout — flexbox and table layout written from the spec, on an integer cell grid.
  • Browser-grade engine — incremental layout, viewport culling, diffed frames, tokenized input.
  • No native code — pure JS all the way to the escape sequences; bun build --compile makes a single binary.
  • Any transport — a TTY, an SSH channel, a WebSocket: if it moves bytes, it can host a session.
